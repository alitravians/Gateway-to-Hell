# بوابة الجحيم — Gateway to Hell

لعبة رعب تعاونية لروبلوكس، مبنية بحيث تكون قابلة للنشر التلقائي من الريبو مباشرة.

## ما الموجود؟

حلقة لعب كاملة قابلة للتشغيل داخل اللعبة:

- **لوبي رعب** من طابقين (قاعة، بوابة مركزية، فوانيس، إضاءة وضباب، لوحة متصدرين)
- **شاشة تحميل** وقائمة رئيسية (Play / Game Modes / Updates)
- **matchmaking** لاختيار عدد اللاعبين (2/4/6) واختيار الطور، مع عدّ تنازلي
- **خريطة القصة** قابلة للاستكشاف مع 5 ألغاز: المفاتيح، الرموز، التماثيل، الشموع، الأصوات
- **مؤقّت المرحلة** وبوابة هروب تُفتح عند حل كل الألغاز
- **الوحش (حارس الجحيم)**: ذكاء مطاردة (patrol / investigate / chase / search) عبر PathfindingService
- **نظام السقوط والإنقاذ**: عند الإمساك يسقط اللاعب، ويمكن لزملائه إنقاذه خلال 60 ثانية
- **أنظمة انغماس**: أماكن اختباء، مصباح يدوي + بطاريات، نظام Sanity بتأثيرات بصرية
- **نهايات متعددة** (جيدة / سيئة / سرّية) و**إنجازات** محفوظة، وأطوار Story/Nightmare/Hardcore/Endless
- **مخطّط للصوت المكاني** (يتطلب تفعيل Voice Chat على التجربة من مالك موثّق)

## الفكرة العامة

- 2 إلى 6 لاعبين، رعب تعاوني
- حل الألغاز والهروب قبل انتهاء الوقت، وإلا يخرج الوحش ويطارد اللاعبين
- واجهات عربية بالكامل مع طابع سينمائي مظلم

## كيف يعمل البناء؟

هذا المشروع لا يعتمد على تعديل ملف place موجود "في مكانه".

بدل ذلك:

1. يقرأ Rojo البنية من `default.project.json`
2. يربط كل خدمة/سكربت مباشرة بملفها داخل `src/`
3. يضمّن Workspace و Lighting كتعريفات داخل المشروع
4. يولّد الملف الكامل:

`GatewayToHell.rbxlx`

هذا يعني أن `src/` هو مصدر الحقيقة الوحيد، وكل build يعيد توليد place من الصفر.

## أوامر مفيدة

### فحص الكود

```bash
python3 publish.py --lint-only
```

### بناء ملف المكان

```bash
~/.local/bin/rojo build . -o GatewayToHell.rbxlx
```

### نشر إلى Roblox

قبل النشر الحقيقي، عدّل القيم التالية في `publish.py`:

- `UNIVERSE_ID`
- `PLACE_ID`

ثم:

```bash
export ROBLOX_PUBLISH_API_KEY="..."
python3 publish.py
```

## البناء داخل المحرّك + مسار Blender المستقبلي

الماب الحالي (اللوبي وخريطة القصة) مبني بالكامل داخل Roblox عبر الكود مع إضاءة وضباب المحرّك، لأن الإضاءة السينمائية شغل محرّك Roblox أصلاً. مسار Blender محجوز للعناصر البطلة المخصّصة لاحقًا:

- تصميم العنصر في Blender وتصديره كـ FBX
- رفعه كأصل 3D عبر Open Cloud
- تحميله داخل اللعبة عبر `InsertService:LoadAsset` واستبدال الشكل الحالي به

هكذا نقدر نرفع جودة أي عنصر تدريجياً دون إعادة كتابة منطق اللعبة.

## ملاحظات التطوير

- استخدم Luau نظيف ومباشر
- لا تخلط منطق الواجهة مع منطق السيرفر
- أي بيانات دائمة يجب أن تمر عبر DataStore مع `pcall`
- أي ريموت جديد يجب إنشاؤه دفاعيًا على السيرفر
